# Concatenate multiverse objects

[`c()`](https://rdrr.io/r/base/c.html) takes the union of the scenarios
in several `pima.multi` objects. The analytical choices within each
object are left as they were generated by
[`create_multi()`](https://livioivil.github.io/pima/reference/create_multi.md);
choices from different objects are not crossed.

## Usage

``` r
# S3 method for class 'pima.multi'
c(..., recursive = FALSE)
```

## Arguments

- ...:

  Two or more `pima.multi` objects. Named arguments supply labels for
  the `.source` column; unnamed arguments are labelled `block1`,
  `block2`, and so on.

- recursive:

  Must be `FALSE`.

## Value

A `pima.multi` object. Model and formula identifiers are reassigned so
they are unique in the result. The `.source` column identifies the
originating object. Specification columns absent from a block contain
`NA` for its rows. All inputs must either have fitted models or have
none.

## See also

Other multiverse construction:
[`create_fit()`](https://livioivil.github.io/pima/reference/create_fit.md),
[`create_multi()`](https://livioivil.github.io/pima/reference/create_multi.md),
[`subset.pima.multi()`](https://livioivil.github.io/pima/reference/subset.pima.multi.md)

## Examples

``` r
a <- create_multi(
  Sepal.Width ~ Sepal.Length + Petal.Width,
  data = iris, focal = "Sepal.Length",
  fit.specs = list(lm = stats::lm)
)
b <- create_multi(
  Sepal.Width ~ Sepal.Length + Species,
  data = iris, focal = "Sepal.Length",
  fit.specs = list(lm = stats::lm)
)
both <- c(width = a, species = b)
both$scenarios
```
